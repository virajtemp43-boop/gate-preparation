# GATE CS/IT — 90-Day Master Preparation Plan

> **Target:** GATE Computer Science & Information Technology (CS)
>
> **Starting level:** Scratch / weak fundamentals
>
> **Preparation window:** Exactly **3 months / 90 days**
>
> **Core strategy:** Learn → Basic Practice → PYQ → Fresh GATE-style Questions → Error Analysis → Revision → Tests
>
> **Primary goal:** Build enough conceptual strength and question-solving ability to perform under GATE time pressure.

---

# 1. The 90-Day Rule

This plan intentionally focuses on **3 months only**.

We are **not** assuming extra time after 90 days. Any additional time that happens to be available later is treated as a bonus, not part of the plan.

### Non-negotiable rules

1. **Do not study randomly from YouTube.** Follow the subject order in this plan.
2. **Do not spend weeks only watching lectures.** Questions must start immediately after learning a topic.
3. **PYQs are compulsory.** They are not optional revision material.
4. **Fresh questions are compulsory.** PYQs alone are not enough because you can memorize patterns.
5. **Keep an Error Book.** Every repeated mistake must be recorded.
6. **Every Sunday is a test + analysis day.**
7. **Do not chase 100% syllabus completion at the cost of understanding.**
8. **Do not skip revision.** A topic is not finished when the lecture ends; it is finished when you can solve questions without help.

# 4. MONTH 1 — Programming + DSA + Algorithms + Mathematics

## Month 1 Objective

Build the foundation first. This month is deliberately heavy on **Programming, Data Structures and Algorithms** because later CS topics become easier when your problem-solving ability is stronger.

### Month 1 Weekly Timetable

| Week | Main Subject | Topics to Complete | PYQ Target | Fresh Question Target | Test |
|---|---|---|---:|---:|---|
| **Week 1** | C Programming | Data types, operators, conditions, loops, functions, arrays, pointers basics | 20–30 | 20–30 | Sunday C test |
| **Week 2** | C + Recursion + DS | Pointers, strings, structs, recursion, linked lists, stacks, queues | 25–35 | 25–35 | Sunday C/DS test |
| **Week 3** | Data Structures | Trees, BST, heaps, hashing, graphs, traversal | 30–40 | 30–40 | Sunday DS test |
| **Week 4** | Algorithms + Math | Complexity, sorting, searching, divide & conquer, greedy, basic discrete math | 30–40 | 30–40 | Sunday mixed test |

### Month 1 Daily Focus

| Day | Main Work |
|---|---|
| Monday | Learn theory + basic examples |
| Tuesday | Continue theory + basic problems |
| Wednesday | PYQs from completed topics |
| Thursday | New GATE-style practice |
| Friday | Mixed PYQs + weak-topic repair |
| Saturday | Timed topic test + revision |
| Sunday | Weekly test + detailed error analysis |

### Month 1 Priority Order

```text
C Programming
   ↓
Recursion
   ↓
Data Structures
   ↓
Complexity
   ↓
Algorithms
   ↓
Discrete Mathematics basics
```

### Month 1 Exit Criteria

By the end of Month 1, you should be able to:

- Read and trace basic C code without panic.
- Understand pointers, recursion and memory behavior at a basic GATE level.
- Solve standard stack, queue, linked-list and tree questions.
- Know major sorting/searching complexities.
- Solve basic graph and heap questions.
- Handle basic recurrence/complexity questions.
- Have completed a meaningful first batch of Programming/DS/Algorithm PYQs.

# 5. MONTH 2 — Core CS Attack

## Month 2 Objective

This is the heaviest core-CS month. Focus on subjects that repeatedly require conceptual understanding plus numerical/problem solving.

### Month 2 Weekly Timetable

| Week | Main Subject | Topics to Complete | PYQ Target | Fresh Question Target | Test |
|---|---|---|---:|---:|---|
| **Week 5** | Digital Logic | Number systems, Boolean algebra, K-map, combinational circuits, sequential circuits | 25–35 | 25–35 | Digital Logic test |
| **Week 6** | COA | Instruction set, addressing, ALU, control, memory, cache, I/O, interrupts, pipelining | 30–40 | 30–40 | COA test |
| **Week 7** | DBMS | ER, relational algebra, SQL, dependencies, normalization, indexing, transactions | 35–45 | 35–45 | DBMS test |
| **Week 8** | Operating Systems | Processes, threads, scheduling, synchronization, deadlocks, memory, virtual memory, file systems | 35–45 | 35–45 | OS test |
| **Week 9** | Computer Networks | Layers, data link, MAC, Ethernet, routing, IPv4, subnetting, NAT, TCP, congestion, DNS, HTTP | 35–45 | 35–45 | CN test |

> **Important:** Month 2 contains 5 weeks. Treat it as the most intensive month. Do not compress DBMS/OS/CN just to say the syllabus is "finished." Understanding matters more.

### Month 2 Daily Focus

| Day | Main Work |
|---|---|
| Monday | New concept block 1 + examples |
| Tuesday | New concept block 2 + basic problems |
| Wednesday | Topic-wise PYQs |
| Thursday | Numerical/problem-heavy practice |
| Friday | Fresh GATE-style questions |
| Saturday | Timed subject test + formula/concept revision |
| Sunday | Weekly mixed test + error analysis |

### Month 2 Special Practice Rules

**DBMS:** Solve SQL, normalization, transaction and indexing problems by hand.

**OS:** Solve scheduling, synchronization, deadlock and memory numericals repeatedly.

**CN:** Practice subnetting, routing, TCP/window/congestion and protocol questions numerically.

**COA:** Draw cache/memory/pipeline situations instead of trying to memorize them.

**Digital Logic:** Practice circuits and truth tables manually.

### Month 2 Exit Criteria

By the end of Month 2, you should:

- Know the standard formulas and models of the core subjects.
- Be comfortable with numerical questions.
- Have solved a large collection of topic-wise PYQs.
- Know which core subjects are weak.
- Have a functioning Error Book with recurring mistakes clearly identified.

# 10. Question Practice Structure

For every topic, follow this exact sequence.

```text
STEP 1 → Learn the concept
        ↓
STEP 2 → Solve easy/basic examples
        ↓
STEP 3 → Solve topic-wise PYQs
        ↓
STEP 4 → Solve fresh GATE-style questions
        ↓
STEP 5 → Record mistakes
        ↓
STEP 6 → Reattempt wrong questions
        ↓
STEP 7 → Take timed test
```

Do not jump directly from lecture to full mock tests.

---

# 11. PYQ Strategy

## First Pass — Learning Mode

While learning a topic:

- Solve PYQs topic by topic.
- Understand the logic.
- Do not worry about speed initially.

## Second Pass — Exam Mode

After finishing a subject:

- Mix the PYQs.
- Hide topic names.
- Set a time limit.
- Solve without notes.

## Third Pass — Revision Mode

In Month 3:

- Reattempt only questions you previously got wrong, guessed, or solved very slowly.

### PYQ Classification

| Label | Meaning |
|---|---|
| **A** | Solved confidently |
| **B** | Solved but slow/uncertain |
| **C** | Wrong / couldn't solve |
| **D** | Completely new concept |

Month 3 should heavily target **B + C + D** questions.

# 15. Revision Cycle

Every important topic should be revised on this cycle:

```text
Day 0 → Learn
Day 1 → 10–15 min revision
Day 7 → Revisit notes + wrong questions
Day 21 → Timed mini-test
Day 45+ → Mixed revision
```

Use the Error Book heavily during the later cycles.

# 16. Error Book Format

Create one notebook or digital file:

```text
GATE_ERROR_BOOK/
│
├── 01_C_PROGRAMMING
├── 02_DATA_STRUCTURES
├── 03_ALGORITHMS
├── 04_DISCRETE_MATH
├── 05_ENGINEERING_MATH
├── 06_DIGITAL_LOGIC
├── 07_COA
├── 08_DBMS
├── 09_OS
├── 10_CN
├── 11_TOC
├── 12_COMPILER
└── 13_GENERAL_APTITUDE
```

For each mistake:

```text
Question:
Topic:
My Answer:
Correct Answer:
Why I Was Wrong:
Concept I Missed:
Shortcut / Observation:
Date:
Next Revision:
```

### Most important rule

If you make the **same type of mistake three times**, stop doing more questions and repair that concept immediately.

# 17. Test Strategy

## Month 1

- 1 subject/topic test each week.
- No pressure on full-paper speed yet.

## Month 2

- 1 subject test + 1 mixed mini-test per week.
- Start measuring accuracy and time.

## Month 3

- At least 1 full mock per week initially.
- Final weeks: increase full-paper simulation.

### Full Mock Conditions

```text
Duration → 3 hours
Environment → No phone
No notes
No pauses
Real exam-style attempt
Immediate analysis after the paper
```

The analysis is as important as the mock itself.

# 20. What NOT to Do

Avoid these common traps:

- Watching 8 hours of lectures and solving 5 questions.
- Collecting PDFs instead of studying.
- Starting every subject at once.
- Memorizing solutions to PYQs.
- Ignoring Mathematics and GA until the final days.
- Giving mocks without analyzing them.
- Studying only easy questions because they feel productive.
- Spending multiple days making beautiful notes.
- Constantly changing strategy after seeing other students' schedules.
- Measuring progress only by hours watched.

# 26. The Main Mindset

You are starting from scratch, so the target is **not**:

> "I must know every topic perfectly in the first attempt."

The target is:

> **Understand the concept → solve standard questions → learn from mistakes → solve unfamiliar questions → repeat.**

The first 30 days will feel slow.

That is normal.

By Month 2, questions should start becoming familiar.

By Month 3, the goal is to recognize patterns quickly and solve mixed questions under time pressure.
